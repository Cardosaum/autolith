#+TITLE: Extraction candidates in the Autolith sources

* Terminal and application
** Layered source-tagged registry (new library, or structlisp)
=src/application/command.lisp= 492-746. Ordered registration layers keyed by
source and name, shadowing, an effective index with collision checks,
snapshot/restore, and remove-by-source. The same shape is written at least four
times: commands, =agent/context.lisp= 241 and 403, =provider/registry.lisp=
148-178 and 444-531, and the MCP registry; =startup/user-init.lisp= 87-90 calls
all four remove-by-source functions in a row. Cut: the extension transaction
macro, =configuration-error=, and the command validation hook.

** Bounded, sanitising, throttled capture streams (new library, or ls-compat)
2026-10-03: the two copies are one. =bounded-output-stream= in
=core/streams.lisp= keeps a structlisp bounded builder prefix and the column on
trivial-gray-streams; the management REPL uses it directly, and
=async-lisp-output.lisp= subclasses it with ANSI stripping, a pending structlisp
deque with omission counts, and the rate-limited sink. Moving the stream into a
library is still open. Cut: only =bounded-string= and =sanitize-text=, both
already from clinedi.

** Reader thread with pause and exclusive ownership (clinedi input pump)
=src/terminal/responsive-input.lisp= 2741-2928. A polling reader thread,
depth-counted pause that joins it, and =call-with-exclusive-input= that runs in
place on the reader thread and otherwise pauses it. Any multi-threaded TUI with
modal pickers needs this, and clinedi's selection session already takes
=read-event= and =input-ready-p= callbacks. Cut: it shares the controller's lock
and condition variable with the work queue, the interrupt hint, the resize
callback, and =configuration-error=. The work queue itself is product-specific.

** Smaller items
- Grouped multi-column picker rows (=ui.lisp= 696-820) are the natural renderer
  for clinedi's =selector-arrange=.
- Path completion under a root with dotfile and =..= policy
  (=path-completion.lisp=): only if clinedi grows a completion protocol.
- Terminal-backed Gray streams for provider authentication (=commands.lisp=
  1852-1985) minus the relay lock check.

* Core, configuration and state

** Multi-file transactional publish with rollback (sexp-store)
=src/state/data-transfer-import.lisp= 230-310 and =data-transfer.lisp= 233-266.
Stages a set of writes with backups, publishes each with a compare-and-swap
against the expected old bytes, restores or deletes on failure, removes
directories it created, and reports rollbacks that leave recovery copies. This
is sexp-store's single-file transaction generalised to many files. Cut:
=data-transfer--fail=, the path check through =platform-path-status=, the
=platform-make-private= and =platform-publish-new-file= primitives,
=make-identifier= for staging names, and a raw =sb-posix:rmdir= at line 299.

** Hardened bounded reader for portable data (sexp-config)
=src/state/data-transfer.lisp= 62-136 and 147-159. Reads one form with every
=#= dispatch disabled except octet vectors, read-eval off, a depth limit and a
byte limit, then rejects cyclic or shared structure; a matching canonical
printer. Exactly sexp-config's job, which would need octet-vector syntax and a
source byte limit. The portability walk overlaps sexp-store's
=record-finite-p= but is stricter.

** Identifier generation (idsmall or ironclad, both already imported)
=make-identifier= (configuration.lisp 1173-1183), =platform-unique-identifier=
(posix 128-142 reading =/proc/sys/kernel/random/uuid= or shelling out to
=uuidgen=, win32 716-738 through BCryptGenRandom). The fallback when both fail
is =get-universal-time= plus CL =random=, which is predictable, while
=data-transfer--temporary= calls its staging names unpredictable. Build a
UUIDv4 from =ironclad:random-data= or use idsmall, and both platform methods go.

* Provider, conversation and inference

Compared against the library versions Autolith pins through qlot, not the
older checkouts under =~/common-lisp=: the pinned cl-llm-provider-api already
has a =/wire= system (Responses, Chat Completions, Anthropic Messages, SSE,
contracts) and the pinned cl-rfc8628 has a managed credential manager, JWT
helpers, redaction, browser opening and request helpers.

** Token refresh repeated across providers, partly copying cl-rfc8628
Refresh exchanges in chatgpt (289-410), =grok/authentication.lisp= 110-221,
=nous/authentication.lisp= 207-376 and gemini 383-404; token POST helpers in
chatgpt 346-375, gemini 256-282, nous 162-193; token-document validation in
chatgpt 377-421 and gemini 284-319. Four copies of the RFC 6749 refresh grant
differing only in endpoint, client, headers and account-id extraction. The
Nous request helper copies =device-authentication-request= adding a deadline,
and the document helpers copy =device-authentication-json-request=. The Nous
cross-process refresh lock that reloads under the lock and adopts a newer
rotation (nous 19-41, 281-376) applies to any rotating refresh token and
belongs in =managed-credential-manager= as a lock hook.

** Responses tool_search over deferred namespaces (cl-llm-provider-api/wire)
=src/provider/wire-protocol.lisp= 129-449: =defer_loading= wire form, the
client-executed =tool_search= declaration, tokenized scored search, and
=tool_search_output= rebuilding on replay. Pure Responses wire behavior;
clinker-transcript already owns =tool-search-item-p=. Cut: the history
trimming special (keyword argument), the structlisp deque, the description
text. The Codex model gate (78-121) and Codex methods (451-546) stay.

** Gemini GenerateContent wire protocol (cl-llm-provider-api/wire)
=src/provider/gemini-code-assist.lisp= 480-632 and 728-890: portable items to
=contents=, function declarations and responses, the SSE consumer, finish
reasons and usage mapping, as a fourth protocol beside the Anthropic one.
=provider-request-object= (634-699) would go through =wire-request= as the
Anthropic client does. The private Code Assist onboarding (349-477) and model
catalog stay; its retry loop (297-326) should use =call-with-bounded-retries=.
Gap: =gemini-code-assist--text-parts= (504-525) silently drops image parts.

** Image preparation for prompts (new small library)
=src/conversation/image-input.lisp= 123-302 (magic bytes and PNG, GIF, JPEG,
WebP dimensions), 304-369 (prefix-only inspection), 371-509 (resize to
provider limits through opticl with atomic publication), 699-718 (data URL
and =input_image= item). Every multimodal client needs this; the detection
part has no dependencies and the item constructor fits clinker-transcript.
Cut: =image-input-error=, platform permission and truename calls,
=make-identifier=, artifact-root and durable-record policy, Codex limits as
parameters. Pasted-path unquoting and =file://= handling (559-600) could go to
clinedi.

** Provider and model registry with discovery cache (cl-llm-provider-api/registry)
=src/provider/registry.lisp= whole file and =openai-compatible.lisp= 169-337.
Layered builtin, site, user and runtime sources with precedence, discovery
under a per-registration lock, merged declared and discovered models, cache,
snapshot and restore. The library already declares a
=model-provider-registration= slot holding an object only Autolith defines.
Cut: =config=, the default window and effort tables, the legacy
=*supported-models*= refresh, =*extension-registration-source*=,
=configuration-error=, and the snapshot cache path (inject a sexp-store-backed
cache function).

** Retry policy aware of streamed output (cl-llm-provider-api engine)
=src/provider/client.lisp= 883-1013 (separate retry cap once output streamed,
=provider-stream-abandoned=, jittered delays), 1015-1056 (refresh once after
401), 725-751 (SSE inactivity deadline, which belongs in =/dexador=). Built
directly on the library's bounded retries and event classes. Cut: Autolith
wording and =authentication-error= as a hook.

** Structured answers from model text and JSON Schema import (cl-llm-provider-api/contracts)
=src/inference/frame.lisp= 192-239 (tolerant JSON extraction from prose or
fences, validation, repair reason) and 295-308 (billable tokens with cached
input discounted, next to the budget settlement); =inference/tools.lisp=
408-474 (JSON Schema to native output schema, the reverse of the library's
existing direction). Cut: the task output-schema wrappers and
=rlm-inference-error=.

** Static API-key credentials (cl-rfc8628 for the source and manager types, clinedi for the hidden prompt)
=src/provider/api-key.lisp= 375-468 (environment source and static manager),
3-172 (multi-provider private key file, can stay), 175-291 (hidden terminal
input with echo off and bracketed paste stripped). The five near-identical
=authentication.lisp= files for anthropic, fireworks, opencode, openrouter and
mistral (about 75 lines each, differing only in data) should collapse into one
data-driven definition regardless of extraction.

** Overrides and copies of pinned libraries
- =client.lisp= 26-34 and 159-168 re-declare the library's own
  =provider-account-label= and =provider-note-response-headers= generics, and
  30-34 and 187-191 replace its default methods; which wins depends on load
  order. The library should ask the registration instead.
- =provider-user-agent= (client.lisp 511-518) duplicates
  =authentication-user-agent=; =provider--epoch-local-time= (657-663) hard-codes
  the epoch offset cl-rfc8628 already encodes; =oauth--base64url= belongs with
  cl-rfc8628's helpers.
- Every provider repeats the same streaming =dexador:post= call (fireworks,
  anthropic, nous, grok, openai-compatible 481-499, client.lisp 560-612); one
  helper in =/dexador= removes it.
- The secret-use counter (=provider/authentication.lisp= 5-67) is already wired
  as cl-rfc8628's =*secret-region-function*=; sbcl-generations could own it as
  a checkpoint guard, otherwise leave it.

* Tools, resources, workers, tasks and the rest

Checked against the pinned versions in =.qlot/dists=, not the older checkouts.

** Revision-gated resource protocol (new library, or bundled with the editor)
=src/resource/protocol.lisp= 5-152 and 254-480, =item-identity.lisp= 10-114.
A strict =scheme:identifier= URI grammar, a per-scheme resolver registry,
generics for capabilities, observe and apply-operations with a base revision,
conditions for stale, denied and unsupported, keyed SipHash snapshot digests,
percent-encoded item URIs. Cut: the =autolith-error= superclass and failure
codes, the child-agent and child-safe predicates (one =resolver-permits-p=),
the readable-schemes policy; observation alias retention (154-252) is tied to
the conversation and may stay. =resource-uri-encode/decode= and the URI octet
predicate hand-roll percent encoding while quri is already a dependency.

** Management REPL socket (image-daemon, as an eval module)
=src/management/repl.lisp= 52-240 (length-prefixed frames), 242-381
(HMAC-SHA256 challenge-response, constant-time compare, zeroing), 384-450
(bounded output stream), 455-733 (serial eval queue with deadlines), 736-972
(Unix socket with stale-path quarantine, loopback TCP, accept loop), 1017-1072.
An authenticated control endpoint for a Lisp image is image-daemon's stated
purpose, yet this runs a second framing and auth protocol beside image-daemon's
packets and bearer token. Cut: the application object, the
=:management-repl-*= settings, platform file helpers, the AUTOLITH read
package, transfer and quiescence. Security note: =management-repl-read-frame=
(163-202) runs before authentication (346) with the full reader and
=*package*= set to AUTOLITH, read-eval off only, so an unauthenticated peer can
intern symbols and send deeply nested forms; sexp-config's bounded reader with
a small grammar fixes that regardless of extraction.

** Bounded s-expression reading and plist validation (sexp-config, sexp-store)
- =task/job-boundary.lisp= 49-224 is a hand-written bounded data-only reader
  (node, depth and string limits, forbidden dispatch, keyword-only symbols):
  sexp-config =read-source= with an allowed-atom predicate.
- =job-boundary.lisp= 344-367 reads a child result artifact of up to 16 MB with
  plain =read= under standard syntax, unbounded depth, interning into CL-USER.
- =job-boundary.lisp= 392-420 duplicates =snapshot-write=.
- Plist schema checks (allowed, unique, required keys plus a proper-list test)
  copy-pasted in =mcp/configuration.lisp= 272-398, =lsp/configuration.lisp=
  47-85, =task/contracts.lisp= 169-237, =management/repl.lisp= 75-115,
  =localgroup/protocol.lisp= 33-40: sexp-config needs a field-spec validator.
- Tagged versioned record predicates in =localgroup/handoff.lisp= 144-169 and
  =startup/active-image.lisp= 95-119 duplicate =record-check=.
- Byte-bounded UTF-8 regular-file readers in =mcp/configuration.lisp= 982-1020,
  =lsp/configuration.lisp= 88-105, =task/agents.lisp= 393-419: a
  =read-source-file :maximum-bytes= in sexp-config; pinned ls-compat already
  opens regular files safely.
- =task/agents.lisp= 441-500 re-implements =validate-tree= for better
  diagnostics; improve the library's diagnostics instead.

** Live-image introspection and reversible redefinition (new library)
=self/apropos.lisp= 24-185 and 235-293 (definition kinds, apropos over defined

* Synthesis

** Where the most lines go
1. Operating-system layer: the generic half of the platform protocol, atomic
   publication, bounded regular-file reads, process reaping and path
   confinement. Target: ls-compat growing a files package.
   - Noted while doing it: the pinned ls-compat already provides
     =file-information=, =stream-file-information=, =open-regular-file=,
     =directory-entries=, =link-file= and =file-mode= with a Win32 backend, so
     the remaining step is to make Autolith's =platform-path-status=,
     =platform-stream-status=, =platform-open-regular-file=,
     =platform-list-directory=, =platform-publish-new-file= and the privacy
     calls delegate to them instead of carrying parallel POSIX and Win32
     implementations. The bounded reader (=core/streams.lisp=) and the path
     confinement (=tools/workspace.lisp=) then follow, since both only need
     that status protocol. Not started.
2. Bounded reading and record validation: sexp-config and sexp-store already
   own this; Autolith re-implements it in at least ten places, two of them
   with real holes (the pre-authentication REPL frame reader, the unbounded
   child result read).
3. Provider authentication: the loopback OAuth login and the refresh grant are
   each written several times and partly copy cl-rfc8628.
4. New libraries worth their own repository:
   - the typed settings protocol
   - the SBCL introspection and reversible redefinition set
   - prompt image preparation.

** Correctness findings surfaced by the survey
- =management-repl-read-frame= uses the full reader before authentication.
- =task/job-boundary.lisp= 344-367 reads untrusted child artifacts without a
  depth bound.
- The identifier fallback in =make-identifier= is predictable while staging
  names claim unpredictability.
- The Gemini loopback callback reader is unbounded; the ChatGPT one is not.
- =gemini-code-assist--text-parts= drops image parts silently.
