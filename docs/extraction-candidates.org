#+TITLE: Extraction candidates in the Autolith sources

* Terminal and application
** Layered source-tagged registry (new library, or structlisp)
=src/core/layered-registry.lisp= holds the list mechanics shared by commands,
=agent/context.lisp= and the MCP registry: ordered registration layers keyed
by source and name, replace and remove in place, remove-by-source, the
effective source-ranked view, and position-preserving restore. Each caller
still wraps them in its own lock, snapshot/restore and effective index with
collision checks (=application/command.lisp= 484-724 is the largest).
Providers moved to =cl-llm-provider-api/registry= on 2026-10-04, whose
layering a shared library could adopt too; =startup/user-init.lisp= calls
every remove-by-source function in a row. Cut: the extension transaction
macro, =configuration-error=, and the command validation hook.

** Bounded, sanitising, throttled capture streams (new library, or ls-compat)
2026-10-03: the two copies are one. =bounded-output-stream= in
=core/streams.lisp= keeps a structlisp bounded builder prefix and the column on
trivial-gray-streams, and =async-lisp-output.lisp= subclasses it with ANSI
stripping, a pending structlisp deque with omission counts, and the rate-limited
sink. Since 2026-10-04 the management REPL captures through image-daemon/eval's
own bounded stream instead. Moving the stream into a
library is still open. Cut: only =bounded-string= and =sanitize-text=, both
already from clinedi.

** Smaller items
- Grouped multi-column picker rows (=ui.lisp= 696-820) are the natural renderer
  for clinedi's =selector-arrange=.
- Path completion under a root with dotfile and =..= policy
  (=path-completion.lisp=): only if clinedi grows a completion protocol.
- Terminal-backed Gray streams for provider authentication (=commands.lisp=
  1852-1985) minus the relay lock check.

* Provider, conversation and inference

Compared against the library versions Autolith pins through qlot, not the
older checkouts under =~/common-lisp=: the pinned cl-llm-provider-api already
has a =/wire= system (Responses, Chat Completions, Anthropic Messages, SSE,
contracts) and the pinned cl-rfc8628 has a managed credential manager, JWT
helpers, redaction, browser opening and request helpers.

** Token refresh repeated across providers, partly copying cl-rfc8628
Refresh exchanges in chatgpt (289-410), =grok/authentication.lisp= 110-221,
=nous/authentication.lisp= 207-376 and gemini 383-404; token POST helpers in
chatgpt 346-375, gemini 256-282, nous 162-193; token-document validation in
chatgpt 377-421 and gemini 284-319. Four copies of the RFC 6749 refresh grant
differing only in endpoint, client, headers and account-id extraction. The
Nous request helper copies =device-authentication-request= adding a deadline,
and the document helpers copy =device-authentication-json-request=. The Nous
cross-process refresh lock that reloads under the lock and adopts a newer
rotation (nous 19-41, 281-376) applies to any rotating refresh token and
belongs in =managed-credential-manager= as a lock hook.

** Responses tool_search over deferred namespaces (cl-llm-provider-api/wire)
=src/provider/wire-protocol.lisp= 129-449: =defer_loading= wire form, the
client-executed =tool_search= declaration, tokenized scored search, and
=tool_search_output= rebuilding on replay. Pure Responses wire behavior;
clinker-transcript already owns =tool-search-item-p=. Cut: the history
trimming special (keyword argument), the structlisp deque, the description
text. The Codex model gate (78-121) and Codex methods (451-546) stay.

** Gemini GenerateContent wire protocol (cl-llm-provider-api/wire)
=src/provider/gemini-code-assist.lisp= 480-632 and 728-890: portable items to
=contents=, function declarations and responses, the SSE consumer, finish
reasons and usage mapping, as a fourth protocol beside the Anthropic one.
=provider-request-object= (634-699) would go through =wire-request= as the
Anthropic client does. The private Code Assist onboarding (349-477) and model
catalog stay; its retry loop (297-326) should use =call-with-bounded-retries=.

** Image preparation for prompts (new small library)
=src/conversation/image-input.lisp= 123-302 (magic bytes and PNG, GIF, JPEG,
WebP dimensions), 304-369 (prefix-only inspection), 371-509 (resize to
provider limits through opticl with atomic publication), 699-718 (data URL
and =input_image= item). Every multimodal client needs this; the detection
part has no dependencies and the item constructor fits clinker-transcript.
Cut: =image-input-error=, platform permission and truename calls,
=make-identifier=, artifact-root and durable-record policy, Codex limits as
parameters. Pasted-path unquoting and =file://= handling (559-600) could go to
clinedi.

** Structured answers from model text and JSON Schema import (cl-llm-provider-api/contracts)
=src/inference/frame.lisp= 192-239 (tolerant JSON extraction from prose or
fences, validation, repair reason) and 295-308 (billable tokens with cached
input discounted, next to the budget settlement); =inference/tools.lisp=
408-474 (JSON Schema to native output schema, the reverse of the library's
existing direction). Cut: the task output-schema wrappers and
=rlm-inference-error=.

** Static API-key credentials (cl-rfc8628 for the source and manager types, clinedi for the hidden prompt)
=src/provider/api-key.lisp= 375-468 (environment source and static manager),
3-172 (multi-provider private key file, can stay), 175-291 (hidden terminal
input with echo off and bracketed paste stripped). The five near-identical
=authentication.lisp= files for anthropic, fireworks, opencode, openrouter and
mistral (about 75 lines each, differing only in data) should collapse into one
data-driven definition regardless of extraction.

** Overrides and copies of pinned libraries
- =client.lisp= 26-34 and 159-168 re-declare the library's own
  =provider-account-label= and =provider-note-response-headers= generics, and
  30-34 and 187-191 replace its default methods; which wins depends on load
  order. The library should ask the registration instead.
- =provider-user-agent= (client.lisp 511-518) duplicates
  =authentication-user-agent=; =provider--epoch-local-time= (657-663) hard-codes
  the epoch offset cl-rfc8628 already encodes; =oauth--base64url= belongs with
  cl-rfc8628's helpers.
- Every provider repeats the same streaming =dexador:post= call (fireworks,
  anthropic, nous, grok, openai-compatible 481-499, client.lisp 560-612); one
  helper in =/dexador= removes it.
- The secret-use counter (=provider/authentication.lisp= 5-67) is already wired
  as cl-rfc8628's =*secret-region-function*=; sbcl-generations could own it as
  a checkpoint guard, otherwise leave it.

* Tools, resources, workers, tasks and the rest

Checked against the pinned versions in =.qlot/dists=, not the older checkouts.

** Revision-gated resource protocol (new library, or bundled with the editor)
=src/resource/protocol.lisp= 5-152 and 254-480, =item-identity.lisp= 10-114.
A strict =scheme:identifier= URI grammar, a per-scheme resolver registry,
generics for capabilities, observe and apply-operations with a base revision,
conditions for stale, denied and unsupported, keyed SipHash snapshot digests,
percent-encoded item URIs. Cut: the =autolith-error= superclass and failure
codes, the child-agent and child-safe predicates (one =resolver-permits-p=),
the readable-schemes policy; observation alias retention (154-252) is tied to
the conversation and may stay. =resource-uri-encode/decode= and the URI octet
predicate hand-roll percent encoding while quri is already a dependency.

** Smaller items
- DONE 2026-10-03: symlink-safe canonicalization and root confinement
  (=tools/workspace.lisp=) now call =ls-compat.posix:canonical-pathname= and
  =pathname-within-p=. cl-skills still carries its own copy (a separate
  repository; switching it means adding ls-compat as a cl-skills dependency),
  and =handoff.lisp= 219-226 keeps its three-line check because it reads the
  resolved pathname afterwards.
- Locating the pinned fff library (=tools/search.lisp= 50-114): clifff.
- A unified manager protocol over one worker versus a pool
  (=workers/lisp.lisp= 200-333): sbcl-workers.

* Synthesis

** Where the most lines go
1. Operating-system layer: the generic half of the platform protocol, atomic
   publication, bounded regular-file reads, process reaping and path
   confinement. Target: ls-compat growing a files package.
   - Noted while doing it: the pinned ls-compat already provides
     =file-information=, =stream-file-information=, =open-regular-file=,
     =directory-entries=, =link-file= and =file-mode= with a Win32 backend, so
     the remaining step is to make Autolith's =platform-path-status=,
     =platform-stream-status=, =platform-open-regular-file=,
     =platform-list-directory=, =platform-publish-new-file= and the privacy
     calls delegate to them instead of carrying parallel POSIX and Win32
     implementations. The bounded reader (=core/streams.lisp=) then follows,
     since it only needs that status protocol. Not started.
2. Provider authentication: the loopback OAuth login and the refresh grant are
   each written several times and partly copy cl-rfc8628.
3. New libraries worth their own repository:
   - prompt image preparation.
