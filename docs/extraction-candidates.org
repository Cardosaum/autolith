#+TITLE: Extraction candidates in the Autolith sources

* Terminal and application

** Fullscreen viewport (clinedi, next to live-region)
=src/terminal/fullscreen.lisp= 5-46, 52-108, 111-167, 288-344, 384-429, and the
=fullscreen-output-stream= at 543-634.
- Unwrapped chunks plus wrapped rows that remember their source offsets, so a
  resize reflows and keeps the same top line; a row-diff painter at absolute
  positions with autowrap off; column to character to click-region mapping; a
  Gray stream that tracks =?1049h/l= and OSC 10/11/110/111 across packet splits
  so a dropped relay client gets its screen restored.
- clinedi already decodes =:click=, =:scroll= and the page keys but cannot
  switch the alternate screen or SGR mouse mode on, so Autolith hard-codes those
  sequences in five places (fullscreen.lisp 73, 100, 629; commands.lisp 2016,
  2033).
- Stays in Autolith: the frame composer, legend, welcome panel, and the message
  header jump (which becomes a row predicate argument). The Win32 console mode
  call maps onto clinedi's posix/win32 transport split; theme enter/leave
  become caller-supplied prologue and epilogue strings.

** OSC 52 clipboard route (sophisticated-clipboard)
=src/terminal/clipboard.lisp= and the host-then-terminal strategy in
=src/application/clipboard.lisp= 21-56. The library has command and Win32
backends but no terminal route, and "host, else terminal" is the standard
remote-session answer. Takes a writer function instead of the UI; notices stay
in Autolith; base64 would come from cl-base64 directly.

** Remaining xterm controls (clinedi ansi.lisp)
OSC 10/11 default colors and their resets (=style.lisp= 268-298), OSC 0 window
title and the =redraw=0= override of clinedi's OSC 133 prompt marker
(=protocol.lisp= 422-460). Small; expose =redraw=0= as a clinedi option rather
than overriding.

** Layered source-tagged registry (new library, or structlisp)
=src/application/command.lisp= 492-746. Ordered registration layers keyed by
source and name, shadowing, an effective index with collision checks,
snapshot/restore, and remove-by-source. The same shape is written at least four
times: commands, =agent/context.lisp= 241 and 403, =provider/registry.lisp=
148-178 and 444-531, and the MCP registry; =startup/user-init.lisp= 87-90 calls
all four remove-by-source functions in a row. Cut: the extension transaction
macro, =configuration-error=, and the command validation hook.

** Live restart debugger core (new library)
=src/application/lisp-machine.lisp= 99-309 with helpers at 27-45 and 70-97.
Runs a thunk with the failing stack kept live, routes every condition through
a selector callback instead of SBCL's debugger, and supports retry,
return-values and abort recoveries through catch tags. Cut: the Autolith
control-condition predicate, =application-present= as the failure callback, the
recovery object protocol, =self-read-form=, and the package. The LLM diagnosis
(=debugger.lisp=) and the terminal modal (lisp-machine.lisp 437-764) are product
UI and stay.

** Bounded, sanitising, throttled capture streams (new library, or ls-compat)
=src/application/async-lisp-output.lisp=, whole file: fixed-capacity Gray
streams with truncation markers, a pending ring with omission counts,
incremental ANSI stripping, a rate-limited sink and column tracking.
=management/repl.lisp= 386-436 is a second, simpler copy. Cut: only
=bounded-string= and =sanitize-text=, both already from clinedi.

** Reader thread with pause and exclusive ownership (clinedi input pump)
=src/terminal/responsive-input.lisp= 2741-2928. A polling reader thread,
depth-counted pause that joins it, and =call-with-exclusive-input= that runs in
place on the reader thread and otherwise pauses it. Any multi-threaded TUI with
modal pickers needs this, and clinedi's selection session already takes
=read-event= and =input-ready-p= callbacks. Cut: it shares the controller's lock
and condition variable with the work queue, the interrupt hint, the resize
callback, and =configuration-error=. The work queue itself is product-specific.

** DONE Record validation re-implements sexp-store (sexp-store record-check)
=src/application/recovery-input-vault.lisp= 39-110 and 280 check tags, versions
and key sets by hand; =sexp-store:record-check= already does that. The same
pattern recurs in =user-operation-context.lisp= 59 and
=state/data-transfer.lisp= 52.

** Clickable widget spans (cl-termdown spans)
=src/terminal/style.lisp= 344-457 and the region bookkeeping in =ui.lisp=
2200-2236 and 2391-2412. Labels carrying action payloads whose character
extents survive concatenation. Only worth moving together with the viewport;

** Smaller items

* Core, configuration and state

** Multi-file transactional publish with rollback (sexp-store)
=src/state/data-transfer-import.lisp= 230-310 and =data-transfer.lisp= 233-266.
Stages a set of writes with backups, publishes each with a compare-and-swap
against the expected old bytes, restores or deletes on failure, removes
directories it created, and reports rollbacks that leave recovery copies. This
is sexp-store's single-file transaction generalised to many files. Cut:
=data-transfer--fail=, the path check through =platform-path-status=, the
=platform-make-private= and =platform-publish-new-file= primitives,
=make-identifier= for staging names, and a raw =sb-posix:rmdir= at line 299.

** Hardened bounded reader for portable data (sexp-config)
=src/state/data-transfer.lisp= 62-136 and 147-159. Reads one form with every
=#= dispatch disabled except octet vectors, read-eval off, a depth limit and a
byte limit, then rejects cyclic or shared structure; a matching canonical
printer. Exactly sexp-config's job, which would need octet-vector syntax and a
source byte limit. The portability walk overlaps sexp-store's
=record-finite-p= but is stricter.

** Identifier generation (idsmall or ironclad, both already imported)
=make-identifier= (configuration.lisp 1173-1183), =platform-unique-identifier=
(posix 128-142 reading =/proc/sys/kernel/random/uuid= or shelling out to
=uuidgen=, win32 716-738 through BCryptGenRandom). The fallback when both fail
is =get-universal-time= plus CL =random=, which is predictable, while
=data-transfer--temporary= calls its staging names unpredictable. Build a
UUIDv4 from =ironclad:random-data= or use idsmall, and both platform methods go.

** Re-implementations of pinned libraries
- =readable-state-property-present-p= (=state/records.lisp= 5-9) equals the
  already imported =sexp-store:record-property-present-p=.
- Hand-written form validators covered by =record-check=, =record-shape-p= or
  =snapshot-read-record=: =preferences--form-p=,
  =project-adaptation--proper-plist-with-keys-p=, =data-transfer--properties-p=,
  =update-state--form-p=. Preferences, permissions and project adaptations also
  hand-roll read, validate, wrap and lock; agendas, memories and papercuts
  already sit on =snapshot-store= and =log-store= transactions.
- Atomic text and byte publication that sexp-store should offer as text or
  octet snapshot writes: =image-commit--write-atomically= (not private, not
  exclusive, bypasses =platform-replace-file=), =project-adaptation-notes-create=
  (temp names from pid plus =random=), =data-transfer--write-export=.
- DONE 2026-10-03 (d9915e93): every =sb-posix:getpid= outside the platform
  files now calls =ls-compat.posix:current-process-id=, and the one
  =sb-posix:rmdir= uses =uiop:delete-empty-directory=.
- DONE 2026-10-03 (ls-compat 52c959f, Autolith cade840b and b5eabc64): the
  28 direct =sb-ext= UTF-8 octet conversions now call
  =ls-compat:utf8-string-to-octets= and =utf8-octets-to-string=, which use
  =sb-ext= on SBCL (so a lone surrogate is still refused) and babel with an

- The =~/common-lisp/sexp-store= checkout is older than the pinned 778ce80 and
  lacks the store and record-check API; compare against the pinned version.

** Duplications to fix in place

* Tools, resources, workers, tasks and the rest

** Line-anchored, revision-gated text edit engine (new library)
=src/resource/workspace-file.lisp= 329-354, 403-468, 471-478, 481-527, 530-821,
823-959. Validates and applies =replace-lines=, =insert-before=,
=insert-after=, =delete-lines= and =replace-empty= against an exact base
snapshot: operations may only target lines the caller saw, carry four-hex
SHA-256 anchors corrected within three lines of drift, reject overlaps, apply
in one pass, and publish atomically with a stale check just before. Any agent
harness or editor wants this. Cut: =tool-error= over JSON hash tables (take
normalized plists, signal library conditions), the observation state object,
platform replace and publish, =daemon-random-token=, the line splitter, and the
bounded reader. The visible-range code (403-468, 496-510) re-implements
structlisp's integer interval set.

** Where the most lines go
1. Operating-system layer: the generic half of the platform protocol, atomic
   publication, bounded regular-file reads, process reaping and path
   confinement. Target: ls-compat growing a files package.
   - DONE 2026-10-03: atomic publication (=ls-compat/files=) and descendant
     discovery, adopted in Autolith at nine sites; see the two DONE items.
   - DONE 2026-10-03: the delegation below, the bounded reader and path
     confinement; see the DONE items above.
   - Noted while doing it: the pinned ls-compat already provides
     =file-information=, =stream-file-information=, =open-regular-file=,
     =directory-entries=, =link-file= and =file-mode= with a Win32 backend, so
     the remaining step is to make Autolith's =platform-path-status=,
     =platform-stream-status=, =platform-open-regular-file=,
     =platform-list-directory=, =platform-publish-new-file= and the privacy
     calls delegate to them instead of carrying parallel POSIX and Win32
     implementations. The bounded reader (=core/streams.lisp=) and the path
     confinement (=tools/workspace.lisp=) then follow, since both only need
     that status protocol. Not started.
2. Bounded reading and record validation: sexp-config and sexp-store already
   own this; Autolith re-implements it in at least ten places, two of them
   with real holes (the pre-authentication REPL frame reader, the unbounded
   child result read).
3. Provider authentication: the loopback OAuth login and the refresh grant are
   each written several times and partly copy cl-rfc8628.
4. Terminal: the fullscreen viewport, hyperlinks, OSC controls and the input
   pump are clinedi's natural territory; the clipboard route is
   sophisticated-clipboard's.
5. New libraries worth their own repository: the line-anchored edit engine
   with its resource protocol, the typed settings protocol, the JSON value
   codec shared by four repos, the live restart debugger core, the SBCL
   introspection and reversible redefinition set, and prompt image
   preparation.
